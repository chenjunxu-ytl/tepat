Rule Book pack

Runs inside the Chrome extension, fetched live from this service. Anyone can submit a proposal for review; accepting proposals happens on the admin machine. Rule IDs are assigned automatically (RB-001, RB-002, …).

Propose a new rule

Give examples, the way the Rule Book does: phrases that should be flagged (Salah) and phrases that must not be flagged (Betul). The pattern is derived from your examples — no regex knowledge needed. The rule number is assigned for you.

Pending proposals

Admin machine only. Accepting appends the rule to the Rule Book pack (backup kept); rejected ones are simply left to close on GitHub.

Word flags (PRPM)

Decisions land in word-overrides.json (the source of truth for word-level rules) and take effect on every lookup immediately. Accept = pick status + definition (from the issue, the reporter, or your own). Reject = close without an override. Commit the file to the repo so other machines pick it up via Fetch from GitHub.

Grammar flags (Rule Book)

Flags on Rule Book rule hits — wrong regex, missing context, over-triggering. Open = awaiting review; closed = handled (rule fixed in pack or rejected).

Server rules

Rules the local scan service applies (source of truth: the GitHub repo; ↻ Fetch from GitHub pulls main — admin machine only). Levels follow the Rule Book: error structural, no legal context · warn context needed, review before acting · note broad reminder. Toggle a rule off to silence it locally; a GitHub sync restores the repo state. Active in full mode only.

About

Tepat answers one question: does this word exist? It highlights suspicious words for human investigation — it never judges correctness automatically.

Red marks: structural rule hits. Amber: needs context. Blue: uncertain forms. Hover a highlight for notes; use the buttons in each result for local evidence, PRPM lookup or a web search.

Absence from a dictionary or corpus does not establish a spelling error. An attested word does not certify grammar, meaning or factuality.
